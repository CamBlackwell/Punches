# 06 — Visualisation (Metal)

> The two `MTKView`-backed renderers: the 128-band Q3 spectrum and the multi-band goniometer. Covers pipeline construction, draw passes, the Metal functions actually in use, and the hand-offs that will bite you.
> Companion: [05-signal-analysis.md](05-signal-analysis.md) (where the data comes from), [10-theming-and-shaders.md](10-theming-and-shaders.md) (the four background shaders, which use a completely different mechanism).

---

## 1. Two unrelated Metal stacks

This is the first thing to internalise. The project compiles **one** `default.metallib` containing all five `.metal` files, but uses it in two mutually exclusive ways:

| | Visualisation | Background effects |
|---|---|---|
| Files | `AudioMeters/Q3SpectrumView.swift`, `AudioMeters/goniometerView.swift`, `AudioMeters/Shaders.metal` | `View/ShaderEffects.swift`, `View/{Water,Fog,TunnelShader,ColormapWarp}.metal` |
| Mechanism | `MTKView` + `MTKViewDelegate` + `MTLRenderPipelineState` | SwiftUI `.colorEffect(ShaderLibrary.…)` |
| Shader annotation | none (classic MSL) | `[[ stitchable ]]` |
| Library source | `device.makeDefaultLibrary()` — `Q3SpectrumView.swift:195`, `goniometerView.swift:348` | implicit, generated by SwiftUI from the build |
| Uniforms | `setVertexBytes` into a device buffer | positional `Shader` arguments |
| iOS minimum | any | 17 (`.colorEffect`) — project targets 26.2, fine |
| Audio-reactive | **yes** | **no** — purely time-driven |

There are **no `[[attribute(n)]]` vertex descriptors anywhere.** All geometry is fetched from a device buffer indexed by `[[vertex_id]]`, and vertex data is built on the CPU each frame. Audio data reaches the GPU as **vertex positions**, never as a texture or a uniform array.

### Structs and buffer layouts that *are* live

```metal
// Shaders.metal:6-9
struct Vertex { float2 position; float4 color; };
// Shaders.metal:11-15
struct VertexOut {
    float4 position [[position]];
    float4 color;
    float pointSize [[point_size]];      // required for point sprites
};
// Shaders.metal:314-318
struct GonioVertex { float2 position; float4 color; float age; };
// Shaders.metal:406-409
struct GonioGlowUniforms { float pointSizeScale; float alphaScale; };
```

| Pipeline | buffer 0 | buffer 1 | buffer 2 | fragment extras |
|---|---|---|---|---|
| Q3 `grid` / `line` | `Vertex*` | `float2& viewportSize` (`setVertexBytes`, 8 B) | — | — |
| Gonio `guide` | `Vertex*` | `float2& vp` (8 B) | — | — |
| Gonio `glow` | `GonioVertex*` | `float2& vp` (8 B) | `GonioGlowUniforms&` (8 B) | `float2 pointCoord [[point_coord]]` |

The vertex array is uploaded with `device.makeBuffer(bytes:length:options: .storageModeShared)` **fresh every frame** (e.g. `Q3SpectrumView.swift:330`, `goniometerView.swift:558-560`). The small uniforms use `setVertexBytes` inline per draw call.

> **⚠️ `GonioVertex`'s stride is 48 bytes, not 36.** The comment at `goniometerView.swift:209-210` says "float2 position + float4 color + float age = 36 bytes". Because `float4`/`SIMD4<Float>` is 16-byte aligned, both Metal and Swift place `color` at offset 16 (8 bytes of padding after `position`) and pad the struct to a multiple of 16. `MemoryLayout<GonioVertex>.stride` is **48**. The two sides agree, so the code is correct — only the comment is wrong. (`Q3Vertex` has stride 32 for the same reason.) If you change either struct, change both and check `MemoryLayout<…>.stride` in a test.

### Pixel space → NDC

Both renderers convert in the vertex shaders using the same convention (documented at `Shaders.metal:259-266, 320-328, 411-424`):

```
x_ndc = (x_pixels / vp.x) * 2 − 1
y_ndc = 1 − (y_pixels / vp.y) * 2          ← Y-flipped
```

so pixel `(0, 0)` is the **top-left** (UIKit/SwiftUI convention). The dead legacy shaders do no conversion at all — they pass `float4(position, 0, 1)` through, so they expect clip-space input. Do not copy their pattern.

> **⚠️ `Q3MetalRenderer` has no thread synchronisation.** `bands`, `peaks`, `enhancedMode` and `inspectFraction` (`:153-156`) are plain `var`s written on the main thread by `updateUIView` and read on the Metal render thread by `draw(in:)`. Array mutation concurrent with a read is undefined behaviour, not merely "a frame of tearing" — the `bands` array in particular is reassigned wholesale every 60 Hz tick by `UnifiedAudioAnalyser` (`:679-683`). The goniometer solves this with `os_unfair_lock`; Q3 does not. See [14-known-issues.md](14-known-issues.md#g2-unsynchronised-q3renderer-state).

### Pipelines (`:194-228`)

```swift
gridDesc.vertexFunction   = library.makeFunction(name: "q3VertexShader")
gridDesc.fragmentFunction = library.makeFunction(name: "gridFragmentShader")
lineDesc.vertexFunction   = library.makeFunction(name: "q3VertexShader")
lineDesc.fragmentFunction = library.makeFunction(name: "q3GlowFragmentShader")
```

Both use the same source-over alpha blend closure (`:201-208`). Note the **naming trap**: the descriptor called `gridDesc` is used for four different passes, and `fillVertexShader`/`fillFragmentShader` exist in Metal but are bypassed in favour of `gridFragmentShader`.

Failure handling is `print`-only (`:196`, `:226`) — a missing library or a pipeline error produces a silently blank view.

### Draw order (`:234-284`)

| # | Pass | Pipeline | Primitive | Function | Notes |
|---|---|---|---|---|---|
| 1 | Grid | `grid` | `.line` | `drawGrid` (`:337-365`) | horizontal dB lines −80…−10, brighter 0 dBFS, 10 vertical frequency lines |
| 2 | Gradient fill | `grid` | `.triangleStrip` | `drawFill` (`:367-395`) | 2 vertices per band, alpha fades to 0 at the baseline |
| 3 | Spectrum line | `line` | `.lineStrip` | `drawLine` (`:397-420`) | the only user of the glow fragment shader |
| 4 | Peak holds | `grid` | `.line` | `drawPeaks` (`:422-447`) | tick = 40 % of band width; **skipped when `peaks[i] <= 0.012`** (`:424`) |
| 5 | Inspect hairline | `grid` | `.line` | `drawInspectLine` (`:449-462`) | only when `inspectFraction != nil` |

Passes 2–4 are gated on `!bandSnapshot.isEmpty` (`:255`). Note the renderer takes `let bandSnapshot = bands` / `let peakSnapshot = peaks` (`:252-253`) — Swift value semantics give `bands` an atomic retain, so the arrays themselves are safe to snapshot; the race is on the `var bands` property read.

### Coordinate mapping (`:286-313`)

| Helper | Formula | Range |
|---|---|---|
| `bandToX(_:count:width:)` | `index / (count - 1) · width` | band 0 at x=0, band 127 at x=width. **Bands are already log-spaced, so this linear index map yields a log axis.** |
| `levelToY(_:height:)` | `(1 − level) · height` | level 1 → top |
| `freqToX(_:width:)` | `(log10 hz − log10 20) / (log10 20000 − log10 20) · width` | the *independent* fourth copy of the log mapping |
| `dBToY(_:height:)` | `(1 − (dB + 90) / 90) · height` | −90 dBFS → bottom, 0 dBFS → top |

> **Gotcha:** `bandToX` maps band *edges* linearly by index while `freqToX` maps the *frequency* the grid line is drawn at. Because the analyser's band edges start at 20 Hz and step logarithmically, the two agree only by construction. The topmost band (index 127) is centred above 20 kHz in the analyser (`UnifiedAudioAnalyser.swift:636-640`) but is drawn at the far right of the axis. See [05-signal-analysis.md](05-signal-analysis.md#9-three-incompatible-frequencyband-conventions).

### `updateSamples` — the band split (`:280-317`)

**Runs on the main thread**, from `updateUIView` (`:193-200`). This is the goniometer's key design decision: unlike the Q3 renderer, all filtering happens in Swift on main, and the render thread only consumes finished band arrays.

```
a300 = 1 − exp(−2π · 300  / sr)          sr = max(sampleRate, 8000)
a3k  = 1 − exp(−2π · 3000 / sr)

per sample:
  lp300L += a300 · (left[i]  − lp300L)     ┐ persistent state
  lp3kL  += a3k  · (left[i]  − lp3kL)      ┘ across calls (:274-275)

  bass[i] = lp300L                          0 – 300 Hz
  mid[i]  = lp3kL − lp300L                 300 Hz – 3 kHz
  high[i] = left[i]  − lp3kL               3 kHz – Nyquist
```

Two cascaded one-pole IIR low-passes. The state is deliberately **persistent** across `updateSamples` calls (comment at `:272-273`) so the filters have memory instead of restarting every frame and producing a click.

`sampleRate` comes from `Float(AVAudioSession.sharedInstance().sampleRate)` at the call site (`:199`), not from the analyser. The `max(sampleRate, 8000)` guard (`:286`) prevents `exp(−∞) → 0` nonsense before the session is configured.

> **Gotcha:** these are **first-order** IIR filters, not the steeper filters the top-level `README.md:25` implies ("splits the incoming signal into three frequency bands using IIR low-pass filters"). First-order gives 6 dB/octave, so the bands overlap heavily. A −3 dB crossover is not achieved at either 300 Hz or 3 kHz. Switching to a 2nd- or 4th-order topology (or a proper crossover with complementary gain correction) is the single biggest fidelity improvement available to this view.

### Draw passes (`:386-433`)

| # | Pass | Pipeline | Detail |
|---|---|---|---|
| 1 | Guides | `guidePipeline` | `drawGuides` (`:437-479`) |
| 2 | Highs cloud | `glowPipeline` | violet `SIMD4(0.82, 0.25, 1.00, 1)` (`:419`) |
| 3 | Mids cloud | `glowPipeline` | cyan `SIMD4(0.08, 0.92, 1.00, 1)` (`:423`) |
| 4 | Bass cloud | `glowPipeline` | orange `SIMD4(1.00, 0.52, 0.06, 1)` (`:427`) |

**Draw order is highs → mids → bass**, i.e. bass last so it renders on top. The comment at `:415-416` explains why: bass is the most mono/central shape and needs to read through the wider clouds.

All three band clouds are gated on `!snap.bassL.isEmpty` (`:412`) and share one `setRenderPipelineState(glow)` call. Each `drawBandCloud` issues **3 `drawPrimitives(.point)` calls**, so the frame totals **9 point draws** (3 bands × 3 glow layers) plus 1 line pass.

> **Stale comments:** `Shaders.metal:399-402` says the renderer "calls `drawPrimitives(.point)` three times per frame (scatter) and twice (trail)", and `goniometerView.swift:242-243` describes a "**Trail pass** — the 150 most-recent points". There is no separate trail pass and no 150-point cap. Trails are an emergent property of the `age`-derived alpha across the 3 glow layers. Both comments describe an earlier design.

### `drawBandCloud` (`:506-578`)

```
mids[i]  = ((left[i] + right[i]) / 2) · gain
sides[i] = ((left[i] − right[i]) / 2) · gain
mids  = smooth(mids)                        // 5-tap [1,4,6,4,1]/16 Gaussian (:485-492)
sides = smooth(sides)

insert 8 lerp steps between consecutive samples → 9× point density
totalVerts = (count − 1) · 9 + 1
```

Then three glow passes with `GonioGlowUniforms`:

| Pass | `pointSizeScale` | `alphaScale` | Effect |
|---|---|---|---|
| bloom | `10.0` | `0.012` | wide ambient haze |
| halo | `4.0` | `0.055` | soft shoulder |
| core | `2.0` | `0.900` | bright solid centre |

The vertex shader formula is `pointSize = (1.2 + age · 2.8) · scale` (comment at `:563-565`), so at `age = 1` (newest sample) the three layers are ~11 px / ~22 px / ~44 px discs. The dense overlapping discs merge into continuous filled shapes — that is how a scatter plot becomes a solid Lissajous figure without any triangle tessellation.

`toPixel(mid:side:center:radius:)` (`:582-587`) is `x = cx + side · radius`, `y = cy − mid · radius`. Radius is `min(width, height)/2 − 14` (`:518`), leaving a 14 pt margin.

`radius` and `center` are passed **by value** into `drawBandCloud`, so zoom (`_zoomGain`) is applied via the `gain` parameter multiplying M and S — i.e. zoom scales the *signal*, not the *coordinates*.

### `drawGuides` (`:437-479`)

| Element | Colour / alpha | Extent |
|---|---|---|
| Inner ring | teal, α 0.07 | 33 % radius |
| Mid ring | amber, α 0.07 | 66 % radius |
| Outer ring | white, α 0.15 | full radius |
| M axis (vertical) | α 0.12 | full diameter |
| S axis (horizontal) | α 0.07 | full diameter |
| L / R diagonals | α 0.18 | `d = radius · 0.707` |

All emitted as `.lineStrip` via `submitRing` / `submitSegment` / `submitLineStrip` (`:591-631`).

> **Cross-file coupling:** `submitRing`, `submitSegment` and `submitLineStrip` build **`Q3Vertex`** arrays — the type declared in `Q3SpectrumView.swift:9`, not in this file. The two renderers are not independent; changing `Q3Vertex` breaks the goniometer's guides too.

### Snapshot pattern (`:319-332`)

`updateSamples` writes six arrays plus `_zoomGain` under `os_unfair_lock_lock/unlock` (`:311-316`); `snapshot()` reads them back under the same lock (`:325-330`) and returns them by value. This is the **only correct cross-thread pattern in the project** and is the model to copy for `Q3MetalRenderer`.

### Unused

`private extension Color { var simd: SIMD4<Float> }` (`:636-643`) is defined and never called — all goniometer colours are literal `SIMD4<Float>` constants. Consequently `ThemeManager.gonioSidesColor` and `gonioMidsColor` (`View/setting_View.swift:922, 925`) are **persisted and previewed in Settings but never reach the Metal renderer.** Wiring them up requires replacing the three literals at `goniometerView.swift:419, 423, 427` with `Color.simd`.

## 5. `AudioMeters/goniometerManager.swift` — read this before you touch the tap

## 6. Change checklist

| If you change… | Re-verify |
|---|---|
| a Metal struct layout | `MemoryLayout<…>.stride` on both sides; `float4` alignment means `GonioVertex` is 48 B and `Q3Vertex` is 32 B |
| a vertex function name | both `Q3MetalRenderer.buildPipelines` (`:194-228`) and `GoniometerMetalRenderer.buildPipelines` (`:347-380`) resolve by string, so a typo is a silent blank view |
| `q3SpectrumBands` normalisation | `levelToY` and `dBToY` in `Q3SpectrumView.swift:296, 310` both assume the −90…0 dBFS mapping from `UnifiedAudioAnalyser.swift:662` |
| goniometer band cutoffs | `goniometerView.swift:287-288` (coefficients) **and** the `updateUIView` sampleRate source (`:199`) |
| goniometer colours | the three literals at `:419, 423, 427`, or wire up the unused `Color.simd` extension |
| the shared `Q3Vertex` type | it is used by the goniometer's guide geometry too |
| draw counts | the frame issues 1 line pass + 9 point passes; any performance work should target `drawBandCloud`'s per-frame `makeBuffer` |
